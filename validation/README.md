# Release evidence

The JSON receipts in this directory are privacy-minimized implementation evidence.

- real-manual.json requires an actual App Server thread/compact/start plus contextCompaction started/completed notifications and the matching plugin ledger events.
- real-auto.json requires an actual model turn to cross the configured automatic-compaction limit. Failure to trigger remains a negative result; it is never replaced by a simulated event.
- installed-package.json is generated from the real installed cache. It covers the Hook/MCP process boundary, a restart, the exact Skill and packaged license, redaction, two-stage task deletion, and a post-delete byte scan.
- installed-host-read.json is generated by `npm run verify:installed-host`. It records an ephemeral read-only Codex model turn that discovered and called the installed context_continuity MCP server exactly once. The successful read creates no task state, leaves Codex configuration unchanged, and stores only hashes of its synthetic input and task reference.
- real-installed-manual.json and real-installed-auto.json run the same App Server lifecycle against Hook files in the installed cache. The automatic receipt contains two completed compactions.
- dsh-package.json packs the root bundle, installs it in an isolated consumer with scripts disabled, verifies the bundle patch, peer boundary, required files and module import, then removes the scratch tree.
- dsh-real-lifecycle.json runs the published `0.1.1-rc.2` Cordis, AgentRegistry, Session, SystemPrompt and ToolRuntime APIs. It verifies native confirmation, schema-valid compaction events, summary exclusion, the real pre-step waterfall, stale action handling and host-bound user provenance. It does not claim a DSH CLI profile install or engine-generated automatic compaction.
- macOS evidence comes from the public `macos-latest` CI matrix, not from these Windows-generated Codex host receipts. An authenticated real Mac Codex automatic lifecycle remains unverified.

The driver injects the vetted repository Hook definitions through thread/start.config.hooks, disables installed plugins for that ephemeral thread, and sets bypass_hook_trust only in the same thread configuration. It aborts before starting if an unrelated non-plugin unmanaged Hook is active, and fails verification if an unrelated Hook nevertheless runs. It does not install the plugin, trust a project, disable another plugin persistently, or change global Codex configuration.

All eight successful receipts bind the release source tree and source Codex
plugin package. The six Codex receipts additionally bind the tested plugin
package; the DSH package receipt binds its isolated tarball, while the DSH Host
API receipt proves the source integration path rather than that tarball.
Receipts exclude prompts, assistant messages, credentials, and raw transcript
content. They prove the stated implementation path, not real-task efficacy.
