# 产品与状态契约

冻结日期：2026-08-28

## 一句话定义

Context Continuity 在压缩、恢复和 Agent 交接前后，保存并核验一小组带来源的任务不变量，使 Agent 从正确目标、约束和工作位置继续，而不是把宿主摘要当成事实。

## 只保护会改变后续动作的信息

MVP 保留以下对象，因为删除任一类都能在冻结评估案例中改变下一步、范围、授权或完成判断：

| 对象 | 典型故障 | MVP |
| --- | --- | --- |
| 当前目标 | 压缩后继续旧目标 | 必须 |
| 硬约束与授权 | 执行越界、发布或删除 | 必须 |
| 用户纠正及覆盖关系 | 旧要求复活 | 必须 |
| 当前决定及仍有效理由 | 重开已关闭选择、重复返工 | 有改变动作时保留 |
| 未决问题与分歧 | 摘要制造虚假共识 | 必须 |
| 工作对象与版本指纹 | 在错误目录或版本继续 | 必须 |
| 经验证的完成状态 | 重做或误报完成 | 必须 |
| 下一步动作 | 恢复后漂移 | 必须 |
| 普通闲聊、完整工具输出、完整 transcript | 不稳定且成本高 | 不保存 |

每条状态都必须有 source_ref、recorded_at、status、authority、verification、supersedes。冲突项可以并列存在；系统不得为了得到单一摘要而合并它们。

## 单一有效状态

有效状态不是某个 Markdown 摘要文件，而是从一个任务的 append-only ledger 投影得到：

1. 原始用户事件和当前可复核证据是最终权威。
2. 若绑定用户意图插件，它拥有 intent namespace；连续性插件不能另写目标、约束、授权或纠正。
3. 连续性插件拥有转换事件、快照、恢复核验、工作对象新鲜度和 handoff capsule。
4. 执行防偏插件只读 execution_guard_view，不得回写有效状态。
5. 宿主摘要、Agent 推断、子 Agent 结果和外部 handoff 一律先作为候选或缓存，不能直接覆盖有效状态。

并发写入使用 expected_generation；不做 last-write-wins。每个事件使用前一事件哈希形成可核验链，状态可以从 ledger 重建。

    用户或证据改变不变量
            |
            v
    增量写入 ledger --PreCompact--> 最小快照
            |                           |
            |                       宿主压缩
            |                           |
            +----PostCompact记录--------+
                                        |
                             SessionStart(compact/resume)
                                        |

                                        |
                +-----------------------+----------------------+
                |                       |                      |
             等价/可修复            非阻塞不确定            高风险不一致
             自动继续               标记后继续              问用户后再动作

每条非空提示都会产生一个有界、脱敏的来源事件，并向 Agent 注入短
task_ref/source_event_id 绑定；这不是摘要，也不触发额外模型。该来源事件只能触发
候选状态，不能证明模型生成的结构化语义。用户权威写入必须先生成完整、可读、绑定
generation 的提案，再由用户在第二条提示中原样确认。只在用户主动保护状态或风险会
影响高风险动作时要求确认，不每轮打扰。快照由生命周期事件触发，不每轮重写摘要。
恢复和子 Agent 启动的模型可见上下文默认预算为 800 tokens、硬上限为 1500 tokens；
超出时按风险优先级裁剪并保留遗漏计数。

## 恢复分类

- equivalent：当前 projection 与快照等价，可静默继续。
- repaired：ledger 有快照之后的更新，选择较新的可核验 projection。
- continue_with_markers：有不影响当前低风险动作的不确定性，显示标记后继续。
- ask_before_high_risk：缺失或冲突可能改变目标、范围、授权、工作对象、发布、删除或其他不可逆动作，只问一个必要问题。

每次 compact、resume 或 SessionEnd 边界都会把原 `next_action` 标记为 stale，因为即使
目标和约束没有变化，动作游标也可能已受工具结果、工作区或宿主摘要影响。Agent 必须
结合当前有效投影重新推导；低风险可带标记继续，高风险动作先询问。

跨会话 resume 不强制要求存在压缩快照。正常 SessionEnd 会记录退出时工作区指纹；
若 ledger、退出指纹和当前工作区一致，可判为 equivalent；若目录、Git HEAD 或
dirty 指纹变化，仍按对应风险升级。

插件运行异常时 Hook 返回 continue: true。这保证宿主仍可工作，但不再声称提供连续性保证。ledger 哈希损坏时，连续性状态本身拒绝恢复；它不会阻止宿主进行低风险工作。

## 丢弃与重建

- clear：保留审计历史，但使当前有效项失效。
- off/on/reset/delete：MCP 都需要明确匹配的第一条请求、一次性 challenge 和第二条精确确认；本地 CLI 使用精确 task_ref 二次确认。reset 追加重置事件并开始新的有效状态；诊断 CLI reset 会先归档旧目录。delete 删除该任务及其精确匹配归档。
- 工作目录、Git HEAD 或 dirty fingerprint 改变时，不自动继承旧完成状态。
- 用户明确的新目标优先于旧快照；通过新增项和 supersedes 更新，不改写旧事件。

## 非目标

不保存完整对话，不做跨项目人物画像，不做语义检索记忆，不自动提升长期记忆，不做任务排程、通用规划、权限判定、工具执行拦截、云同步或第二套 Agent Harness。
